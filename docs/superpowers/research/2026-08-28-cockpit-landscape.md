# Cockpit landscape research (2026-08-28)

Scope: what overlaps cockpit design v4 (meta-harness in tmux, steer loop, Documents/Records lineage, git-tracked state, tmux-as-TUI, harness-improvement loop). Sources via Exa; all 2026 unless noted. Verdicts: **adopt** / **borrow** / **ignore**.

## 1. Claude Code native features (highest impact)

- **Agent view** — `claude agents` · https://code.claude.com/docs/en/agent-view · Research preview: dispatch background sessions from one screen, rows show working/needs-you/done, `Space` peek+reply, `Enter` attach, `/bg` moves a running session in; each dispatched session gets its own worktree; `Notification` matchers `agent_needs_input`/`agent_completed` fire while it's open. **Relevance: adopt as a spawn mode.** Overlaps `cockpit spawn agent` + fleet status for Claude-only fleets. Background sessions have no tmux pane, so the agent layer needs a "headless" agent kind tracked purely via hooks.
- **`--agent <name>` main-thread agent** · https://code.claude.com/docs/en/sub-agents · A session can run *as* a subagent definition: its system prompt, tools, model, and **frontmatter hooks** apply to the main thread. **Adopt.** Define `~/.claude/agents/cockpit.md` and launch `claude --agent cockpit`; role-scoped hooks replace the `COCKPIT_ROLE` env-var branching and the SessionStart "load the cockpit skill" injection. `--agents '{json}'` gives per-spawn ad-hoc worker roles.
- **Cross-session messaging** — `ListAgents`/`SendMessage` (v2.1.224+) · https://code.claude.com/docs/en/cross-session-messaging · Claude sessions message each other on this machine, across machines, and on the web. **Adopt.** The cockpit Claude can deliver steer records to a worker directly; `tmux send-keys` becomes the fallback for non-Claude agents and humans.
- **Hooks reference** · https://code.claude.com/docs/en/hooks · Events we didn't account for: `PostCompact`, `TaskCreated`/`TaskCompleted` (can block completion → "tests must pass"), `TeammateIdle`, `InstructionsLoaded`, **`FileChanged`** (watch literal filenames), `WorktreeCreate`/`WorktreeRemove` (replace git behavior), `StopFailure`, `PostToolBatch`; handler flags `async: true` and **`asyncRewake: true`** (background hook wakes Claude on exit 2). **Adopt.** Marker hooks go `async`; `doc lint` can `asyncRewake` instead of warning inline; a `FileChanged` hook on a worker's steer record delivers steer without keystrokes; `WorktreeCreate/Remove` register tracks automatically.
- **Worktrees** — `claude --worktree <name>`, `EnterWorktree`, `.worktreeinclude`, default location `.claude/worktrees/<name>` · https://code.claude.com/docs/en/worktrees · **Borrow.** Keep `~/dev/worktrees/` (cross-repo tracks) but honor `.worktreeinclude` and use the `WorktreeCreate` hook so Claude-created worktrees show up as tracks.
- **Agent teams** (experimental) · https://code.claude.com/docs/en/agent-teams · Lead + teammates, shared task list at `~/.claude/tasks/<team>/`, JSON mailboxes, `teammateMode: tmux` split panes, delegate mode (Shift+Tab), no worktree isolation. **Borrow.** A track can run as a team inside its window; the `tasks` record should mirror the native task list rather than invent one. Docs say split-pane is "not supported in Ghostty" — verify whether that applies when already inside tmux.
- **Run agents in parallel** overview · https://code.claude.com/docs/en/agents · Also `/batch` (5–30 worktree subagents → PRs), dynamic workflows, `/fork`, `/subtask`. **Borrow** as spawn modes; cockpit orchestrates *which* mode, not the mode itself.

## 2. Terminal meta-harnesses / orchestrators

- **gigantsc/maestro** · https://github.com/gigantsc/maestro · Local-first conductor: on-disk `.maestro/` state (missions, features, assertions, handoffs, checkpoints, memory), no daemon, handoff launches build a self-contained markdown brief and start a fresh Codex/Claude run. **Borrow.** Closest to our Records model; its handoff brief and validation *assertions* are worth copying into the `handoff` and `tasks` templates.
- **markuswondrak/AgentMux** · https://github.com/markuswondrak/AgentMux · PM→Architect→Plan→Code→Review state machine; file-watching orchestrator advances when artifacts appear; prompts injected into tmux panes. **Borrow** the "artifact appears → state advances" pattern (our `FileChanged`/records approach), ignore the fixed pipeline.
- **indiekitai/orchestration-playbook** · https://github.com/indiekitai/orchestration-playbook · "Loop Engineering": evidence levels, dispatch contract, acceptance rules. **Borrow** evidence labels as a `status`/`evidence` field on Records.
- **dimileeh/agent-workspace-fabric**, **frizynn/gralph**, **tzone85/project-x**, **arbazkhan971/loop-orchestrator**, **safethecode/orc**, **amoreX/agent-orchestrator**, **strIDEterm** (commercial Worker+Judge) — worktree-per-task, PRD→DAG, PR-monitor loops, auto-merge. **Ignore** for v1 (autonomous pipelines, not human-in-the-loop cockpits); gralph's per-run artifact directories echo our Documents layout.
- **greenforestpath/wezterm_automata (wa)** · https://github.com/greenforestpath/wezterm_automata · Rust "terminal hypervisor": capture all panes → pattern engine → event bus → workflows; Robot Mode JSON API + MCP; strict observe/act separation with policy gates. **Borrow** the observe/act separation and policy gating; **ignore** the engine (WezTerm-only, pane-scraping we don't need).
- **multiagentcognition/wezterm-agent-mcp** · https://github.com/multiagentcognition/wezterm-agent-mcp · 41 MCP tools to spawn/read/inject/recover agents across WezTerm. **Borrow the idea**: expose `cockpit` as an MCP server so the meta-agent gets typed tools instead of shelling out.
- Zellij: **kaankoken/zj-agents** (Rust WASM engine+sidebar, idle/working/blocked classification), **richhaase/maestro**, **doublenot/zellai**, **stanislc/zellij-claude-teams** (tmux shim). **Ignore** (Zellij), but zj-agents shows the sidebar-rail form factor works as a plugin.

## 3. Annotate-in-editor → send-back prior art

- **backnotprop/plannotator** · https://github.com/backnotprop/plannotator · 8.1k★, Apache-2.0. Hooks into plan mode and code review for Claude Code/Codex/Copilot/Gemini/OpenCode/Pi; annotate markdown/HTML/diffs/PRs; feedback goes back to the agent; `plannotator archive` of plan decisions. **radekska/plannotator.nvim** replaces the browser with nvim buffers (`gc` comment, `gs` suggestion, `gd` delete, approve/deny). **Adopt or wrap** as the plan/diff annotation backend; our value-add is the `why` taxonomy, lineage, and git-tracked steer records it lacks.
- **felipeva/codereview-annotator.nvim** · https://github.com/felipeva/codereview-annotator.nvim · Typed annotations (bug/fix/suggestion/nitpick/issue), queue + batch + preamble, `since-batch` diff, adapters (`send`, `pick_target`, `open_diff`), ships its own ADRs. **Adopt-candidate**: the adapter contract maps cleanly onto `cockpit annotate` / `review send`.
- **vuki656/review.nvim** · https://github.com/vuki656/review.nvim · Typed comments, `:Review send` to a tmux pane, auto-refresh while the agent writes. **Borrow** auto-refresh + tmux target.
- **rufex/ceibo.nvim**, **colewhitley/agent-review.nvim**, **shaunchander/hunk-review.nvim**, **ribelo/annotator.nvim** — same loop with markdown/JSON export or file-drop + trigger message. **Borrow** agent-review's "write file, send one trigger line" delivery (matches steer records).
- **tannaurus/nvim-arbiter** · https://github.com/tannaurus/nvim-arbiter · Rust (nvim-oxi) review workbench; line-anchored threads with streaming agent replies; **"review memory": conventions you enforce are extracted into future prompts**; project rules with TOML frontmatter. **Borrow**: validates the feedback→rules loop; precedent for Rust inside nvim if we ever want it.

## 4. Feedback → config loops

- **daegwang/self-learning-agent** · https://github.com/daegwang/self-learning-agent · Polls `~/.claude/projects` + `~/.codex/sessions`, AI reviews sessions on `/review`, writes approved suggestions into CLAUDE.md/AGENTS.md with backup. **Adopt-candidate** for §8 retro instead of building.
- **jack60810/claude-evolve** · https://github.com/jack60810/claude-evolve · Learns from corrections *and* behavior, fitness-scores rules, prunes, promotes to skills. **Borrow** scoring/pruning; too autonomous to adopt wholesale.
- **hornjason/agentgrit**, **demiurge-chiron** (corrections→rules, cross-agent), **Kulaxyz/self-learning-skills**, **googlarz/agents-sync** (one source → N tool files). **Borrow** ideas; all infer from transcripts — none capture *human-tagged why* on a steer, which is cockpit's distinctive input.
- **engn-dev/meta-harness-studio** · https://github.com/engn-dev/meta-harness-studio · Canonical `.harness/` projected to 6 tools + `harness optimize` loop from execution traces, per **Meta-Harness paper arXiv:2603.28052**. **Borrow** the proposer/evaluate/Pareto framing for §8 v2–v3; read the paper before designing A/B.

## 5. Agent-document conventions

- **Kiro specs** (requirements/design/tasks triple) · https://kiro.dev/docs/specs/ ; **GitHub Spec Kit** (constitution + `.specify/memory/`) and **spec-kit-memory-hub** (`docs/memory/` decisions/bugs); **OpenSpec** (change proposals); **BMAD** (`spec-{slug}/`, `.memlog.md`) · https://arceapps.com/blog/sdd-frameworks-analysis-spec-kit-openspec-bmad/ , https://docs.bmad-method.org/reference/workflow-map/ . **Borrow**: add a `spec` kind between `prd` and `design` (Fowler's spec-first/anchored/as-source taxonomy: https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html ; PRD-vs-spec-vs-design distinction: https://nimbalyst.com/blog/spec-driven-development-with-coding-agents/ ).
- **Memstem frontmatter spec** · https://github.com/Memstem/memstem/blob/main/docs/frontmatter-spec.md · uuid-v7 ids, `provenance.{source,ref,ingested_at}`, `confidence: extracted|inferred|ambiguous`, `deprecated_by`, `links`, validation-on-ingest. **Borrow** `confidence` and `deprecated_by`; keep our human-readable `<track>/<seq>` ids.

## Decisions this should change (ranked)

1. **Cockpit role = `claude --agent cockpit`** with a `~/.claude/agents/cockpit.md` definition (system prompt, tools, model, frontmatter hooks). Drop `COCKPIT_ROLE` env branching and the SessionStart skill-injection hack.
2. **Steer delivery**: primary = cockpit Claude → `SendMessage` to the worker session; secondary = worker `FileChanged` hook on its steer record path; `tmux send-keys` only for non-Claude agents/humans. `review send` writes the record, then delivers by the best available channel.
3. **Agent layer gets a headless kind**: agent-view background sessions and `claude -p` runs tracked via hooks only; `cockpit spawn agent --mode pane|background|team|batch`. Spike agent view before building our own fleet table.
4. **Hooks**: marker hooks `async: true`; `doc lint` via `asyncRewake`; `WorktreeCreate/Remove` auto-register tracks; `TaskCompleted` gate for "tests pass"; add `PostCompact` to the compaction flow.
5. **Annotation backend**: spike plannotator(.nvim) and codereview-annotator.nvim before writing `annotate.lua`; wrap whichever fits, adding `--why` + `id@sha:line` + steer-record commit. Build from scratch only if both fail.
6. **Records**: mirror Claude's native task list (`~/.claude/tasks/`) as the `tasks` record when a track runs as a team; add maestro-style assertions and playbook evidence levels to `handoff`/`tasks` templates.
7. **Documents**: add `spec` kind; add `confidence` and `deprecated_by` frontmatter fields.
8. **§8 retro**: evaluate self-learning-agent / claude-evolve as the retro engine; frame v3 A/B per the Meta-Harness paper. Cockpit's unique contribution stays the human `why`-tagged steer stream.
9. **Optional**: expose `cockpit` as an MCP server (typed tools for the meta-agent) — cheap with the Python MCP SDK once the CLI exists; adopt wa's observe/act separation as a rule for hooks vs verbs.
10. **Rust**: no case for a Rust TUI (tmux is the toolkit); nvim-arbiter shows nvim-oxi is viable if a Lua hot path ever needs it.
