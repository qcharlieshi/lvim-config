Herdr's native agent states (`idle|working|blocked|done`) + `events.subscribe` push replace the hand-built status rules for tty agents; cockpit **pushes** semantic state for background/stream workers via `pane.report_agent`, making herdr the single status plane; server restart natively re-runs `claude --resume <id>`. Hands-on = `cockpit attach` opening `herdr session attach` in a tmux pane (verified 2026-09-15: headless is first-class, agent detection is server-side, clientless restart-resume fixed in 0.8.0 #2064). All herdr protocol assumptions are quarantined in `supervisor.py` (rented and disposable, same rule as `runtime.py`); the CLI passes **explicit pane/agent ids only** (#2900) and runs with notifications/sounds disabled (#3217).

**v7 changes (from v6):** strategy pass — the judgment layer is unchanged; the runtime layer is reclassified **rented and disposable**. Vendor-native orchestration (Claude Code background agents, `SendMessage`/`ListAgents`, Workflow) and Herdr (the agent-state-aware mux bundled with Omarchy 4.0, 2026-08) are commoditizing spawn/status/mux/worktrees, so `--mode background` becomes the default spawn mode and stream mode is demoted to an optional module (`runtime.py`) built last if at all, with every Claude Code-internal protocol assumption quarantined there. Steers now **address artifacts, not sessions** (`review send <id>`, lazy resolution to the producer or a seeded successor). New invariant: the **artifact plane is flat** — process depth unbounded, artifact depth exactly 1; the operator is a dispatcher, never a relay in the steering path. Build order inverted: CLI core → artifacts → steer loop first; supervisor/stream plumbing last, pending a Herdr-on-macOS spike. §1 gains the build-vs-rent test, flow metric, and thesis; §10 gains the positioning rationale (translation/LILT precedent).

## 1. Purpose

Cockpit is a **meta-harness**: it does no engineering work itself. It orchestrates inner harnesses (Claude Code sessions today; other agent CLIs later), renders what they produce as context, and closes a **steer loop** — document or diff → annotate in Neovim → send back to the agent. Every steer is evidence the inner harness fell short, so the same loop later points at the harness itself (CLAUDE.md, skills, hooks, allowlists).

A principal engineer works with all-CLI tools and a vim grammar. **Neovim is the hood** — windows are panes, tabpages are tracks, floats are dashboards, and **agents are buffers**: a worker's output stream is rendered as text, so `/`, yank, operators, and annotation work over it natively. A **cockpit Claude** is always present as the operator you talk to; a thin **`cockpit` CLI** is the spine both of you drive. **tmux** (the outer session you already live in) is the shell and hosts the TTY-only tools; **herdr**, running headless underneath, keeps worker processes alive and reports agent state as a first-class pane property.

Target loop: _pick worktrees → agents work → review documents/diffs in nvim → steer → agents revise → harness learns._

**Build vs. rent (v7).** Every component sorts by a dead-end test — a layer is **rented**, not built, when (1) a funded team is building it generically, (2) it accrues no data or conventions of ours, and (3) switching later costs nothing we built. Spawn/status/mux/worktree plumbing fails the test (Anthropic's native orchestration; Herdr): rent it, quarantine every vendor-protocol assumption so the runtime is swappable. The artifact model, the why-tagged steer loop, and the nvim review surface pass it — no vendor builds them, and their value compounds in `feedback.jsonl` and muscle memory: build those.

**Flow metric.** The goal is one _grammar_, not one toolbox. Flow is lost to attention surfaces with different grammars, not to multiple sessions — so every feature is judged by whether it reduces grammars touched per hour. nvim owns what is text; tmux hosts what is stubbornly a TTY; tools that already work are not wrapped for completeness.

**Thesis.** The agent industry is sprinting toward fire-and-forget for market reasons: autonomy is the fundable narrative, the current buyer mix is low-stakes, tests are a partial mechanical oracle that defers (not solves) the judgment problem, and judgment capture compounds too slowly for growth-stage vendors. Translation already ran this arc — raw MT won the zero-stakes segment and human-in-the-loop became the durable equilibrium above the stakes threshold (the LILT model). Cockpit is the personal-scale version of that flywheel: why-tagged human corrections as the training signal for the harness. Known risk: per-artifact steering may have a bounded value window if model quality outruns it; the artifact discipline survives either way, and the steer dataset is precisely what would show when steering stops paying.

## 3. Architecture

```
tmux session cockpit-<goal>                 (sessionizer; detach/attach = the whole cockpit)
├─ window 0  nvim  COCKPIT=1                the hood — the only window you look at
│    tab 1 "main"    inbox · STATE.md · documents · diffs · :terminal claude --agent cockpit
│    tab 2 "feat-x"  agent buffers (rendered streams) · document · diff
│    tab N …
├─ window lnav / gh-dash                    TTY tools; viewed by select-window or `cockpit grab`
└─ window (on demand)  herdr session attach cockpit-<goal>     hands-on escape hatch

herdr server — headless                     (owns worker PTYs; never rendered; restart re-resumes agents)
└─ session cockpit-<goal>
     workspace feat-x    pane: claude (impl, tty)     herdr-detected idle|working|blocked
     workspace feat-y    …

~/.cockpit/<goal>/                          state (git)  ←  cockpit CLI  ←  cockpit Claude · hooks · nvim keys
~/.cockpit/<goal>/agents/<track>/<role>/     in.fifo · out.ndjson · needs_you.json · decision · settings.json · marker.json  (ignored)
~/dev/worktrees/<repo>/<branch>/             code (their own repos)
```

The diagram shows `tty` workers; under the default `--mode background` workers are `claude --bg` processes with no herdr pane — pane rows apply only to `tty`/`stream` agents. Herdr injects `HERDR_SOCKET_PATH`/`HERDR_WORKSPACE_ID`/`HERDR_PANE_ID` into managed panes, alongside cockpit's `$COCKPIT_*`.

- `cockpit spawn agent --mode stream` creates the worker pane (`pane.run` in the track workspace), its FIFO/NDJSON pair, its `settings.json` (hooks + pinned permission keys), sends an `initialize` control request, records `pid`/`session_id`/`account` into `marker.json`, and tells nvim (bridge) to open the agent buffer in the track tab.
- Hooks in worker sessions inherit `$COCKPIT_DIR`, `$COCKPIT_TRACK`, `$COCKPIT_AGENT` — they know who they are without heuristics.
- The cockpit Claude drives nvim through `nvim_bridge.py` (existing) and workers through `cockpit`. It never touches the herdr socket or FIFOs directly.
- nvim never runs worker processes itself (`jobstart` was rejected: jobs die with nvim; the herdr pane + FIFO survives, and the process tolerates stdin EOF and resumes when a new writer opens the FIFO — verified).
- Hands-on escape hatch: for `stream` agents, `cockpit attach <agent>` stops the headless process (SIGINT, exit 0) and opens `claude --resume <session_id>` in a `:terminal`; `cockpit detach` relaunches it headless with `--resume` (sessions shared across modes, verified). For `tty` agents, `cockpit attach` opens `herdr session attach` in a tmux window focused on that pane — upstream tolerates tmux nesting but won't chase its edge cases (#2135); the known flaky key is modified Enter, so the Ghostty `shift+enter=text:\n` keybind must go (step 1); `herdr terminal session observe|control` is the scriptable alternative. Detach with the herdr detach key — `session stop` kills the agents.

## 4. Workspace & git tracking

```
~/.cockpit/                    one git repo
  .gitignore                   */agents/  */events.jsonl  */metrics.jsonl
  templates/<kind>.md          Document/Record templates
  worker-settings.json         template: hooks + pinned permission keys (rendered per worker)
  operator-settings.json       PreCompact/SessionStart/Stop hooks for the operator
  views/<name>.yaml            layout presets (tracked)
  <goal>/
    STATE.md                   session record: goal, tracks, agents, views, decisions, next steps
    documents/<track>/<seq>-<kind>-<slug>.md        user-facing
    documents/<track>/<seq>-codediff-<slug>.patch   CodeDiff body (the .md is its sidecar)
    records/<track>/<seq>-<kind>[-<qualifier>].md   agent-facing
    annotations/<seq>-<round>.md                    {ref: id@sha:line | file:range, why, text}
    feedback.jsonl             steer taxonomy stream (tracked)
    tracks/<name>/track.json   repos, branches, worktree paths (tracked; symlinks are ignored conveniences)
    agents/<track>/<role>/     in.fifo · out.ndjson · needs_you.json · decision · settings.json · marker.json (ignored)
    events.jsonl  metrics.jsonl                     machine streams (ignored)
```

**Git rules**

1. Only the CLI commits, serialized by `flock ~/.cockpit/.git/cockpit.lock`. Hooks write files; commits happen on verbs (`doc new/save`, `annotate`, `review send`, `state set`, `snapshot`, `track add/rm`).
2. Structured messages are the human event log: `doc(feat-x/03 plan r2): worktree per repo` · `steer(feat-x/04 → feat-x/impl): 3 annotations` · `state: decision — …` · `snapshot: pre-compact`.
3. Commit judgment, ignore telemetry. Documents are excerpts (≤ 1 MB); the log of record is the worker's `out.ndjson` plus Claude Code's own transcript at `~/.claude/projects/<cwd-slug>/<session_id>.jsonl`.
4. `git log -p <doc>` is a document's version history; `git diff <sha> STATE.md` is "what changed while I was away". lazygit / delta / difftastic / gitsigns work on this repo as views.

**Compaction (cockpit Claude)**: agent-definition rule — update `STATE.md` after any spawn/layout/decision, before replying. `PreCompact` → `cockpit snapshot` (commits topology + agent table). `SessionStart` on `compact|resume` → inject `STATE.md`, `git log --oneline -20` of the session dir, latest Handoff records. Both hooks live in `operator-settings.json`, not the agent file.

## 5. Agent layer

**Spawn modes** (`spawn agent <track> --mode …`):

- `background` (default, v7) — `claude --bg` sessions; surfaced from `claude agents --json`; steered by verbatim delivery of steer records over `SendMessage` (mechanical relay — see steer delivery); `claude attach <id>` for hands-on. Rented plumbing: spawn/status/steer ride vendor primitives, and cockpit owns only the artifact conventions around them.
- `tty` — interactive `claude` in a herdr pane (anything that needs a real terminal). Herdr detects `idle|working|blocked` zero-config and re-runs `claude --resume <id>` on server restart, so `marker.json` shrinks to what herdr doesn't carry. Steered by `agent.prompt` (below); viewed by `cockpit grab` or `cockpit attach` (herdr client in a tmux window). Agent teams run with in-process display (split-pane team display assumes tmux — verify; if it hard-requires tmux, team tracks fall back to `--mode background`).
- `stream` (opt-in; build step 6, only if mid-turn injection and buffer-rendered streams prove worth owning) — headless worker as in §3. `--settings` renders `worker-settings.json` with `permissions.defaultMode`, `skipAutoPermissionPrompt: false`, and the hook block pinned, so a user's global settings cannot change the gating contract. Trim MCP for workers (`--strict-mcp-config` + a cockpit `--mcp-config`) — cold start is 10–13 s with the user's four servers, ~3 s per trivial turn after. **All Claude Code-internal protocol assumptions (stream-json frames, control requests, the gate hook) live in one module — `runtime.py` — with the spike findings as comments: disposable by design.** **Preferred transport if this step runs (2026-11-10): ACP** (Agent Client Protocol) instead of `stream-json`. It's a documented, multi-vendor surface: `session/prompt`/`update`/`cancel` replace the FIFO frames, and `session/request_permission` replaces the `PreToolUse` gate. That makes `runtime.py` an ACP client rather than a reverse-engineered protocol. Two blockers: the billing spike, and the adapter must outlive nvim (§13).
- `batch` — one-shot `claude -p --output-format stream-json`, output captured as a Document.
- `--billing sub|api` — `api` adds `--bare` + `ANTHROPIC_API_KEY`; default `sub`.

**Worker protocol** (stream mode; all verified in the spike):

- Turn: `{"type":"user","uuid":…,"message":{"role":"user","content":"…"},"parent_tool_use_id":null}` written to `in.fifo`. Mid-turn writes are injected into the running turn (one `result`, one `Stop`); there is no queue to model. `--replay-user-messages` echoes each as `isReplay: true` — the write-ack.
- Readiness: `system/init` arrives **per turn**, not at spawn. Send `{"type":"control_request","request_id":…,"request":{"subtype":"initialize"}}` right after launch; the response carries `pid`, `account`, `current_permission_mode`, `models`, `commands`, `agents`.
- Stop button: `{"type":"control_request","request_id":…,"request":{"subtype":"interrupt"}}` — turn ends with `result.subtype = error_during_execution`, worker survives. Close: SIGINT (exit 0). Kill: SIGTERM (exit 143, turn left unfinished; `--resume` continues it). Never use SIGINT as "stop".
- Session id: from `SessionStart` hook or first `system/init`; cached in `marker.json`; not visible to `claude agents --json --all`.

**Permission gate** (`PreToolUse`, matcher `Bash|Write|Edit|NotebookEdit|WebFetch|mcp__.*`, hook `timeout` ≈ 300 s): the hook writes `needs_you.json` `{tool_name, tool_input, since}`, polls for `decision` (`allow|deny [reason]`, tmp+rename), emits `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow|deny","permissionDecisionReason":"…"}}`, removes `needs_you.json`. Timeout → output discarded → Claude Code's built-in deny; fail-closed. The hook self-bounds its polling (Claude Code does not kill it). **The stream carries no pending-permission signal** — `needs_you.json` is the only truthful source. `cockpit approve|deny <agent>` writes the decision; the inbox `y`/`n` and the operator both call it.

**Worker hooks** (in `settings.json`, `async` where allowed, always exit 0, tmp+rename): `SessionStart` → marker (`session_id`, `transcript_path`); `UserPromptSubmit` → `working` (does not fire for mid-turn injections); `Stop` → `idle` + `last_assistant_message` (use it; don't parse the transcript); `SubagentStart/Stop` → subagent list; `SessionEnd` → `offline`; `WorktreeCreate/Remove` → auto-register/deregister tracks; `PostToolUse(Write)` on `documents/|records/` → `doc lint` via `asyncRewake`; `PostToolUse(Bash: gh pr create)` → `announce pr_opened`.

**Status rules**: pane-hosted (`tty`) agents take herdr's states — `agent.list` snapshot + `events.subscribe` push (`pane.agent_status_changed`; working→idle flips lack an event, so `supervisor.py` keeps a 2 s `agent.list` reconcile poll); `blocked` is their `needs_you`. Stream/background workers keep the hand-built rules — `needs_you` iff `needs_you.json` exists (the only truthful gate source); `working` from `UserPromptSubmit` or an `assistant` frame newer than the last `result`, capped to `idle` after N minutes of silence; `paused:quota` from a `rate_limit_event` frame (unverified) — and are **pushed into herdr** via `pane.report_agent`/`workspace.report_metadata`, so the herdr sidebar is the single status plane for all modes. `offline` when the pane is gone (`pane.*` events) or `pid` missing. A lower-confidence source never clears `needs_you`. Never infer permission state from the transcript.

**Steer delivery** (`review send <id>` — addresses the artifact, not a session): commit the steer Record first (idempotent, retryable — the feedback data exists regardless of delivery), then resolve lazily: producer alive and idle → deliver (`SendMessage` for `background`, one user frame on the FIFO for `stream`); producer mid-turn → confirm first (a send is injected, not queued); producer gone or compacted → spawn a successor seeded with the steer, the document, and its `context`/`handoff` records. Delivery is always the CLI relaying the record verbatim — never the operator paraphrasing. `tty` agents: **`agent.prompt`** with `wait: {until: idle}` — delivery ack built in, replacing the v6 paste protocol. Its mid-turn semantics are unverified (inject vs queue): until tested, the resolver's mid-turn confirm applies to `tty` sends too, and `agent.send_keys` is the fallback primitive. `background` agents: operator `SendMessage`.

Agents started outside cockpit still show up: inside the cockpit session herdr detects any `claude` pane zero-config; elsewhere (a bare terminal, sidekick in a non-cockpit tmux session) hooks still fire and they surface as unmanaged `tty` agents with no FIFO.

## 6. Artifact model — Documents and Records

### Documents (`documents/<track>/`) — for the user

| Kind       | Sections                                                                          | Budget                |
| ---------- | --------------------------------------------------------------------------------- | --------------------- |
| `research` | Question · Sources · Findings · Recommendation · Open questions                   | ≤ 600 words + sources |
| `prd`      | Problem · Users · Must/Should · Success metrics · Out of scope                    | ≤ 800                 |
| `spec`     | Requirements · Acceptance criteria · Interfaces · Constraints                     | ≤ 800                 |
| `design`   | Overview · Architecture · Components · Data flow · Failure modes · Open questions | ≤ 1500                |
| `adr`      | Context · Decision · Alternatives · Consequences                                  | ≤ 300                 |
| `plan`     | Goal · Non-goals · Approach · Steps (checkboxes) · Risks · Test plan              | ≤ 1000                |
| `codediff` | `.patch` + sidecar: Intent · Files · Risk · How to test                           | sidecar ≤ 150         |
| `review`   | Verdict · Blocking · Non-blocking · Questions (each `file:line`)                  | ≤ 400                 |
| `digest`   | What happened · Decisions · Needs you — distilled from `out.ndjson` / transcript  | ≤ 200                 |

### Records (`records/<track>/`; `STATE.md` at session root) — for agents and progress

| Kind      | Purpose                                                             | Budget            |
| --------- | ------------------------------------------------------------------- | ----------------- |
| `state`   | cockpit truth                                                       | —                 |
| `tasks`   | per-track checklist: status · owner agent · blocked-on              | one line per task |
| `handoff` | on Stop/PreCompact: done · next · gotchas · files touched           | ≤ 200             |
| `context` | curated files + key `file:line`s + decisions to seed an agent       | ≤ 40 entries      |
| `steer`   | packaged annotations delivered by `review send`: `ref · why · text` | —                 |

### Naming, identity, lineage

```
documents/feat-x/03-plan-worktree-per-repo.md     records/feat-x/04-steer.md · 05-handoff-impl.md
```

- One per-track sequence shared by both branches; `id: <track>/<seq>` is the stable handle. `kind` is the closed enum above. Slug ≤ 40 chars kebab-case.
- **Revisions are commits**: rewrite the same path, bump `revision`, append to `lineage.steered_by`. `supersedes` only when a new id replaces an old one.
- **Annotations reference `id@sha:line`** so a comment stays anchored to the exact revision.

```yaml
id: feat-x/03
kind: plan
title: Worktree per repo
status: draft # draft | in-review | approved | superseded | rejected
revision: 2
created: 2026-08-28T14:02:11-04:00
updated: 2026-08-28T15:40:03-04:00
budget: 1000
confidence: high # research / digest only
producer:
  {
    role: impl,
    agent: feat-x/impl,
    session_id: 7f3a…,
    transcript: ~/.claude/projects/…/7f3a….jsonl,
    model: claude-opus-5,
  }
lineage:
  derives_from: [feat-x/01, feat-x/02]
  steered_by: [feat-x/04]
  supersedes: null
  code: [lilt-mcp@feat/x:9f8e7d6]
consumers: [user] # user | agent | both
tags: [cockpit, feat-x]
```

**Mechanics**: templates in `~/.cockpit/templates/<kind>.md` (frontmatter skeleton + headings + one-line guidance; Templater-compatible so Documents mirror into Obsidian unchanged). `cockpit doc new <kind> --track x [--from id…]` fills `producer` from env and allocates the seq; `doc save` bumps revision and commits; `doc lint` validates schema, sections, budget (warns, never blocks); `doc lineage <id>` renders a Mermaid graph (nvim `diagram.lua`).

## 7. `cockpit` CLI

Single Python script, alias `cockpit`. Front-end agnostic; every key and every meta-agent action is one of these verbs.

| Group             | Verbs                                                                                                                                                                                                                                                                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace         | `init [--goal]` · `up` (ensure outer tmux session + headless herdr server + window 0 nvim with `COCKPIT=1`; nvim starts the operator) · `status [--json\|--pretty]` · `snapshot` · `state set goal\|decision\|next "…"` · `log [--track]`                                                                                                                            |
| Tracks            | `track add <name> --repo r [--repo r2] [--branch b] [--from main]` · `track pick` (fzf over `git worktree list`) · `track repo add` · `track rm`                                                                                                                                                                                                                     |
| Agents            | `spawn agent <track> --role r [--mode background\|tty\|stream\|batch] [--billing sub\|api] [--primary <repo>] [-p] [--resume]` · `send <agent> "…"` · `interrupt <agent>` · `approve\|deny <agent> [--reason]` · `stop <agent>` (SIGINT) · `kill <agent>` (SIGTERM) · `attach\|detach <agent>` · `grab <agent\|pane>` (`pane.read --source recent` → scratch buffer) |
| Views             | `view <target> pr <url> \| diff [--track] \| doc <id> \| agent <agent>` · `view save\|load\|undo <name>`                                                                                                                                                                                                                                                             |
| Documents & steer | `doc new\|save\|lint\|list\|lineage` · `annotate <id@sha:line\|file:range> "…" --why <tag>` · `review send <id> [--round n]` (resolves the producer lazily)                                                                                                                                                                                                          |
| Events            | `announce <kind> [json]` · `metric <name> [json]` · `events --follow` (herdr `events.subscribe` merged with gate/marker files, NDJSON) · `last` (repeat)                                                                                                                                                                                                             |

Agent names: `<track>/<role>` (`feat-x/impl`, `feat-x/review`); `op` is the operator. `send`/`interrupt`/`approve` are the only writers to a worker's FIFO and decision file. Every herdr call goes through `supervisor.py` and names its target explicitly — no `--current`, ever.

## 8. The nvim hood

`lua/cockpit/` in this config, loaded only when `COCKPIT=1` (so the daily config is untouched). Windows are panes, tabpages are tracks, floats are dashboards, agents are buffers; the vim grammar is native. **Ownership is keyed by track id, never by tabpage handle.** A tab is only where a track is shown right now: never destroy state on `TabClosed`, look up windows across all tabs (`win_findbuf`, not `bufwinid`), and keep no mutable state in `vim.t`, which returns copies. These are agentic.nvim ADR 0008's failures.

**Agent buffers** (`cockpit://agent/<track>/<role>`, `stream.lua`): tail `out.ndjson` with `uv.fs_event` (poll fallback) and render frames with extmarks — turn headers (`user` incl. `isReplay` injections), `assistant` text, folded `tool_use`/`tool_result` pairs (`K` or `za` expands), `result` footers with duration/cost, `system/permission_denied` and `rate_limit_event` as warning lines, `[Request interrupted by user]` as a marker. Follow-mode auto-scrolls and suspends when you move away (coact.nvim pattern). Motions: `]]`/`[[` turns, `]t`/`[t` tool calls. Keys: `<leader>ks` prompt → `cockpit send`; `<leader>ki` interrupt; `y`/`n` on a pending gate. Read-only, `nomodifiable`; `/`, yank, and the annotate operator work because it's text. Hidden buffers cost an append.

**Inbox** (`<leader>ka`, oil.nvim model): one line per agent, `needs_you` first, then `working`, `idle`, `paused`, `offline` — `● feat-x/impl  needs_you  Bash: git push …  2m`. `<CR>` open its agent buffer in the track tab · `y`/`n` approve/deny · `s` send (prompt) · `i` interrupt · `x` stop (confirm) · `X` kill · `t` hands-on attach · `o` its latest Document · `dd` dismiss. Refreshes from one `cockpit events --follow` stream plus `uv.fs_event` on `needs_you.json`; a view over CLI state, never a second source of truth.

**Documents buffer** (`<leader>kd`): the track timeline (documents + records interleaved). `<CR>` open · `gl` lineage · `gs` revisions · `p` preview float. **Tracks buffer** (`<leader>kt`): `<CR>` switch tabpage · `a` add · `x` rm.

**Fleet float** (`status.lua`): counts + per-track rows, toggled with `<leader>kf`; incline/lualine segment `● 2 ◐ 1 ✋ 1`.

**The one terminal**: `claude --agent cockpit --settings ~/.cockpit/operator-settings.json [--resume <cached id>]` as a `:terminal` in the main tab. Rules from the mux precedent: never map `<Esc>` in terminal mode; park the cursor at the tail on `WinLeave`; per-key `nvim_chan_send` shim for `<S-CR>` (`\x1b[13;2u`) since libvterm doesn't forward CSI-u; `<M-Space>` leaves terminal mode. `<leader><leader>` → prompt sent to it via `chan_send` (rebinds LazyVim's default; `<leader>ff` remains). TTY agents (`--mode tty`) are pulled into a scratch buffer with `cockpit grab` or opened hands-on via `cockpit attach` (herdr client in a tmux window); they are never attached inside nvim (it reintroduces the emulation cost).

**Motions across views**: `]a [a` next/prev agent buffer · `]t [t` tracks (tabpages) · `m1–9`/`'1–9` window marks.

**Document overlay** (`cockpit.markdown` filetype for `documents/` and `records/`): annotate as an **operator** `<leader>kc{motion}` / visual → text → `--why` picker → `cockpit annotate` with `id@sha:line`; `]d [d` next/prev document; `]r [r` steer rounds; `gl` follow `derives_from`; `gL` lineage graph; `gs` `git log -p` split; `gS` diff vs previous revision; `<leader>kS` `review send` to the producer. The same operator works in agent buffers (ref = `agent@turn:line`). Steer taxonomy: `missing-convention` `wrong-assumption` `missed-context` `style` `scope-creep` `bug` `question` `approve`.

**Views as presets** (`~/.cockpit/views/<name>.yaml`): tabpage layout + what each window shows. Shipped: `fleet`, `review` (diff · document · producing agent buffer), `watch` (N agent buffers in follow-mode), `plan` (document · tasks · agent). `view save` snapshots the current tabpage; `view undo` pops the layout stack.

**Viewer tools in tmux windows**: lnav (over `out.ndjson`/transcripts with `-c` presets), hwatch, delta/difftastic/hunk, gh-dash, fx, glow. Home-manager additions: `difftastic hunk gh-dash fx glow hwatch`.

**Prior art to spike before writing `annotate.lua`**: codereview-annotator.nvim, agent-review.nvim, plannotator.nvim. For `stream.lua`: hangar.nvim (headless `claude -p` dashboard + transcript tail), agent-workbench.nvim (sessions as buffers), coact.nvim (extmark streaming + follow-mode), **agentic.nvim** (most mature: an ACP client with tool-call folds, permission diff preview and hunk navigation). Its ADR 0001/0002 are required reading: streaming `set_lines` into a `wrap` + `foldexpr` buffer makes the viewport jump, so use manual folds with fold state preserved across hide, and draw block borders with `statuscolumn`, not inline virt_text. Adopt if it fits; otherwise borrow the shape.

## 9. Cockpit Claude (operator)

`~/.claude/agents/cockpit.md` — system prompt and tools; launched by nvim's main tab as `claude --agent cockpit --settings ~/.cockpit/operator-settings.json`. Its `session_id` is cached by `SessionStart` so an nvim restart resumes it.

Rules of engagement:

- Read `STATE.md` + `cockpit log -20` before acting; write `STATE.md` after acting.
- Never `stop`/`kill` an agent it didn't spawn, never `send` into an agent mid-turn, without confirming — a mid-turn send is injected, not queued.
- A **dispatcher on the flat artifact plane, never a relay in the steering path**: it routes, digests, and arranges views; steers flow through `review send`'s resolver verbatim, and the operator paraphrases judgment in neither direction.
- Prefer changing a _view_ to explaining in prose; replies stay short — the user is looking at buffers.
- One nvim per repo; cross-repo agents get cwd = primary worktree + `--add-dir` for the rest. The Bash write-guard can fire for paths inside `--add-dir`; the gate hook is what unblocks it.
- Keep its own context small: high-judgment low-token work itself (layout, `STATE.md`, routing steers, approvals); delegate token-heavy reads (digests) to `--mode batch --model haiku` workers.
- Emits Documents via templates like any agent; its `digest`s are how the user catches up.

Hooks: `operator-settings.json` → `PreCompact` → `snapshot`; `SessionStart(compact|resume)` → inject state; frontmatter `Stop` → `handoff` record (the one lifecycle hook frontmatter supports).

## 10. Harness-improvement loop (second spec; v1 emits the data)

**Positioning (v7).** The industry runs the other way — fire-and-forget, auto-review — for market reasons (§1 thesis), not because steering lacks value; translation settled on human-in-the-loop above the stakes threshold, and no vendor is building workflow-level judgment capture because it compounds too slowly to fund. Consequence: **emit `feedback.jsonl` and `metrics.jsonl` from day one, defer the mining** — `retro` is the layer most likely to arrive from outside, and whatever arrives will want this data. The why-tagged steer stream is the one non-commoditizable asset in this spec.

| Phase       | Feature                                                                                                                                                                                                                                                                                                                          | Needs from v1                                  |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| v1          | Steer taxonomy on annotations → `feedback.jsonl`                                                                                                                                                                                                                                                                                 | `annotate --why`                               |
| v1 plumbing | Telemetry → `metrics.jsonl`: per-turn usage/cost/duration from `result` frames; gate decisions and wait times from `needs_you`/`decision`; compactions, subagent fan-out, tool errors from hooks; optional `CLAUDE_CODE_ENABLE_TELEMETRY=1` OTel (`claude_code.tool_decision`, `permission_mode_changed`) into a local collector | worker hooks + stream                          |

Human `why`-tagged steers are the distinctive input no existing tool captures.

## 11. Failure modes & testing (Prototype tier)

- Not in tmux / no herdr server / ambiguous agent / dead bridge socket → clear error, list candidates, never guess, no partial state; `up` ensures both the tmux session and the headless `herdr server`.
- Herdr: socket path must fit macOS `sun_path` (104 chars) — default `~/.config/herdr` socket, never a per-goal socket under a deep dir; protocol bumps can require stopping old servers (pin via nixpkgs, restart on upgrade). Config: headless fallback size ~200×50 (default 80×24 cramps agent output), notifications/sounds off (#3217), `resume_agents_on_restore=true`, **`pane_history` off** (plaintext scrollback at rest; our logs live elsewhere). tmux-resurrect: never add herdr to `@resurrect-processes` — herdr restores its own panes.
- FIFO with no reader → `send` opens `O_NONBLOCK`, fails fast with `offline`; never blocks the CLI or nvim.
- Worker process gone → `offline`; `spawn --resume` relaunches on the cached `session_id` with full continuity (verified).
- Gate hook: `timeout` → fail-closed built-in deny; stale `needs_you.json` older than the hook timeout is shown as `expired`, not pending. Hooks never block or fail an agent otherwise: exit 0, tmp+rename, time-boxed parsing.
- Cockpit `--settings` pins `skipAutoPermissionPrompt: false` and `permissions.defaultMode`; a user-level setting that suppresses the prompt path silently breaks the gate (found in the spike).
- Git: stale `cockpit.lock` > 60 s is broken and logged; a failed commit never loses the file write; `doc lint` warns, never blocks.
- Hand-edited unparseable `STATE.md` → `snapshot` writes `STATE.md.new`.
- `scripts/cockpit-smoke.sh`: the primary path is `--mode background` (`spawn → SendMessage round-trip → doc new → annotate → review send` resolver, including the producer-gone → successor branch); the stream-mode assertions below apply only once build step 6 exists. Stream path: throwaway tmux + herdr sessions; `init → track add → spawn agent --mode stream → initialize probe → send "PONG" → Stop marker → send gated Bash → approve → marker file exists → interrupt → doc new plan → doc lint → annotate → review send → snapshot → stop → track rm`; asserts on `status --json`, `git log`, `out.ndjson` frames, `list-windows`, and `herdr api snapshot`. Happy path only.

## 12. Build order

v7 inversion: judgment layer first, plumbing last — the original order front-loaded the most perishable component.

1. **CLI core**: git tracking layer (repo, flock, commit helpers); `init/up/status/snapshot/state/log`; `track *`. Status from `claude agents --json` + hooks — no supervisor/FIFO plumbing yet; home-manager tool additions incl. `herdr` (≥ 0.8.0) + its launchd user agent; move outer tmux prefix off `M-Space` (frees it for nvim terminal-escape); remove Ghostty's `shift+enter=text:\n` keybind (breaks modified-Enter through nested muxes).
2. **Artifact model**: templates, `doc new/save/lint/list/lineage`, frontmatter schema.
3. **Steer loop**: spike the three annotation plugins; `annotate --why`, `id@sha:line` refs, `review send <id>` resolver → steer record + delivery; `feedback.jsonl`. Works from day one against plain interactive sessions (delivery degrades to the tty paste protocol) — the dataset starts accruing before any runtime exists.
4. **Operator + spawn + supervisor**: `~/.claude/agents/cockpit.md`, `operator-settings.json`, nvim launches/resumes it; `supervisor.py` (herdr socket client: session/workspace/pane, `agent.list`, `events.subscribe` + 2 s reconcile, `agent.prompt`, `pane.report_agent`); `up` ensures the headless server (sessionizer untouched); `spawn --mode background|tty|batch`; **verify `agent.prompt` mid-turn semantics** (gates deleting the `send_keys` fallback) and agent-teams in-process display under herdr.
5. **nvim hood (file-viewing parts)**: `lua/cockpit/` — inbox/documents/tracks buffers, fleet float, operator terminal + `<leader><leader>`, motions and marks, document overlay, views save/load/undo.
6. **Stream runtime (optional, disposable)**: `runtime.py` — `worker-settings.json` template; `scripts/hooks/cockpit-marker.sh` + `cockpit-gate.sh`; `spawn agent --mode stream` (window, FIFO, NDJSON, settings, `initialize` probe, `marker.json`); `send/interrupt/approve/deny/stop/kill`; `stream.lua` renderer; lnav presets over NDJSON; `vim` alias → per-goal socket; `nvim_bridge.py --socket`. Only if mid-turn injection + buffer-rendered streams prove worth owning over interrupt + `SendMessage`; re-check hangar/coact/agent-workbench/agentic.nvim first and adopt if matured; build on ACP rather than `stream-json` if the §13 ACP spikes pass.
7. **Telemetry plumbing** → `metrics.jsonl` from hooks (background mode) or `result` frames + gate timings (stream mode).
8. Later: `retro`, A/B (second spec) — deferred until `feedback.jsonl` has volume (expect the mining layer to arrive from outside); `attach/detach` hands-on flow; native task-list mirroring for team tracks.
